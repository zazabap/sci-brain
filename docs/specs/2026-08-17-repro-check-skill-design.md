# repro-check skill — design

**Date:** 2026-08-17
**Status:** Approved design, implemented in the same PR
**Home:** sci-brain plugin, `skills/repro-check/`
**Issue:** QuantumBFS/sci-brain#41 — "A third party reviewing skill, using agent to
reproduce the result, which exactly should match paper result and show usefulness."
**Reference protocol:** a manual reproducibility fact-check of a numerical-methods
manuscript (theme "T10 — reproducibility and uncertainty reporting"), which supplied
the disclosure-classification scheme and the report protocol generalized here.

## Goal

A general third-party reproducibility review: point the skill at a paper — arXiv
link/ID, DOI, local PDF, or local source — and it determines whether every
results-bearing table, figure, and in-text number can be regenerated by an
independent group from the paper plus the artifacts the paper itself declares
(GitHub repos, Zenodo deposits, data-availability statements), and, when the user
authorizes execution, actually regenerates what it can and compares numbers.

## Why two levels

Reproducibility failure has two distinct causes with different costs to detect:

1. **Disclosure gaps** (cheap to find, no code run): a knob the results depend on
   is neither stated in the paper nor recoverable from artifacts the paper points
   to. "Read the code" without the paper saying *which* code encodes the knob is
   already a finding.
2. **Execution gaps** (require running): the declared pipeline exists and is
   documented but does not regenerate the printed numbers — broken entry points,
   missing data, silent version drift, or genuine mismatch.

So the skill is tiered: **Level 1 (disclosure audit)** is the default and never
executes artifact code. **Level 2 (execution audit)** is opt-in, budgeted, and
climbs a cheapest-first ladder: re-render from committed results → re-evaluate
from committed models/data → full re-training only with explicit approval.

## Asset-centred, not section-centred

The unit of review is the **results-bearing asset**: each numbered table, each
quantitative figure/plot, each headline number in prose. Phase 1 builds an asset
inventory (id, claim, source pipeline, key printed numbers); every later phase
and the final scorecard key off asset ids. Papers without code releases are still
reviewable: every asset resolves to BLOCKED with the missing-artifact finding,
which is itself the review's product.

## Match policy (the "exactly should match" clause)

Declared per asset **before** comparing, never after seeing the output:

- **exact** — deterministic pipeline, printed precision is the tolerance
  (a printed `31.42` matches any output rounding to `31.42`);
- **tolerance** — deterministic modulo floating-point/backend; match within the
  paper's printed last digit, deviation reported;
- **statistical** — stochastic pipeline; match within the paper's own reported
  spread (±σ, seed range); if the paper reports no spread, that is a Level-1
  finding and the comparison uses an explicitly stated ad-hoc band.

Silently downgrading a policy after a mismatch is forbidden; a downgrade must be
reported as a finding.

## Verdicts

Per asset: `REPRODUCED-EXACT` / `REPRODUCED` (within declared policy) /
`PARTIAL` / `MISMATCH` / `BLOCKED` (artifact missing/broken) /
`NOT-ATTEMPTED` (budget or Level 1 only — with the command that would attempt it).

## Safety rails

- Never edit the paper or the artifact repos; the only outputs are the report
  directory and scratch clones/envs.
- Pin and record artifact commit hashes; prefer a tag/release the paper names.
- Run third-party code only after user consent, in an isolated environment
  (repo's declared Docker/lockfile preferred, else a fresh venv), never with
  elevated privileges.
- Confirm before long jobs or large downloads; record wall-clock and environment
  (Python/OS/GPU, package versions) in the report.
- Nondeterminism caveat: exact-match failures on GPU-reduction-order noise are
  reported as tolerance matches with the cause named, not as MISMATCH.

## Deliverable

`docs/repro/<paper-slug>/report.md` (+ `logs/`), structure fixed by
`report-template.md`: verdict paragraph → scorecard table → severity-sorted
findings (each with disclosure class, evidence trail of where the paper AND the
artifacts were searched, and a suggested one-sentence disclosure fix) →
parameter-disclosure matrix per pipeline → out-of-scope one-liners. Evidence
before assertion: an "undisclosed" verdict documents the search on both sides.

## Reuse

- **download-ref** — paper acquisition (arXiv/DOI metadata, PDF, rendered
  markdown) and shallow artifact clones (`.raw/repos/`), when a KB is in use;
  standalone mode uses a scratch directory with the same layout.
- **paper-reviewer** — severity conventions (high/med/low) and the comment-first,
  non-destructive operating principle.
- **figure-taste** — report-only discipline; scorecard-style delivery.

## Non-goals

- Judging scientific merit or novelty (that is refereeing, not reproduction).
- Verifying claims against the *literature* (paper-reviewer's fact-check does that).
- Building a permanent validation harness (autoresearch-validator's job).
